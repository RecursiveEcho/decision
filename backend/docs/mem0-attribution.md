# 自动记忆的方法来源与实现边界

本模块借鉴 Mem0 v1.0.0 的“从用户原话提取候选事实，检索旧记忆，再协调 ADD / UPDATE / DELETE / NONE”流程，在现有 Java/PostgreSQL 中独立实现；没有接入 Mem0 SDK、Python 服务、向量数据库或额外模型服务。

核对的官方源码：

- [Mem0 v1.0.0 prompts.py](https://github.com/mem0ai/mem0/blob/v1.0.0/mem0/configs/prompts.py)：用户消息提取约束及记忆操作类别。
- [Mem0 v1.0.0 memory/main.py](https://github.com/mem0ai/mem0/blob/v1.0.0/mem0/memory/main.py)：候选提取、旧记忆检索及新增/更新/删除协调。
- [Mem0 v1.0.0 LICENSE](https://github.com/mem0ai/mem0/blob/v1.0.0/LICENSE)：Apache License 2.0。

本模块重写提示与代码，没有复制上游提示里的示例或“信息来自互联网”自述。实际来源是绑定的当前用户原话；sourceMessageId / sourceQuote 可回查。引述、附件、模型输出、第三人、假设和合成场景不作为用户个人事实。

检索使用中文二元组与英文词的局部词法相关度，相关优先、最近次之，最多12条相关/本问题记忆与4条稳定全局补充；这不是向量语义检索。稳定性和个人陈述识别使用保守规则，可能漏记复杂表达；不可宣称完美理解自然语言。

一次聊天响应可同时给出候选操作，无额外模型调用。候选先通过原句、作用域、目标版本、幂等与墓碑验证，再在聊天保存事务中写入。手动纠正/删除会建立墓碑、保护手动改动，并使先前检索快照失效；自动写入不增加聊天的全局context_revision。需要重述被遗忘内容时，必须是墓碑之后的新用户原话。

候选内容必须保留完整本人断言和否定，不能把“我不喜欢喝咖啡”截成“喜欢喝咖啡”；所在句的遗忘命令、否认和过去事实不能截取成新记忆。UPDATE/DELETE 需在当前同一句原话中明确包含完整旧事实，或明确指向已存的主题对象（从“挑选/选购/购买 X 时”“选 X 按”等结构提取）。主题保留在内部元数据，跨更新持续有效；所有可访问 active 记忆中同主题不唯一时拒绝主题推断，不受检索前 16 条截断影响。词法相似、泛谓词或模糊代词不足以授权修改；否定删除、否定遗忘和无法确定的双重否定不会执行。部分复杂口语仍会保守跳过。

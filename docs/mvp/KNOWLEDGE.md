# 讨论后沉淀知识与 Obsidian

开始：2026-11-05（Asia/Shanghai）。状态：实施中，尚未完成工程验收。

## 已确认目标

个人使用；本人不写笔记。先正常与 AI 讨论，AI 对照已有知识提出新增、合并、修订裁剪或暂不保存建议；本人审阅具体提案后确认入库。条件不同保留各自条件，未决冲突保留争议，错误结论修订；保留出处和历史。AI 自动多领域分类与链接，Obsidian 作为本机单向浏览镜像。

## 本轮实现

- 独立 knowledge_entry / knowledge_proposal，与自动更新的旧 Topic 和 Wiki 并存。旧主题、全部聊天和个人记忆不自动升级为已确认知识。
- 现有对话提供“整理入库”入口，使用当前对话文字、正式来源及有界的跨对话已确认知识生成一个可审阅提案；可以继续聊天再重新整理，或不保存。准备、确认、略过有明确独立状态。
- 本人确认对应持久化提案，服务端检查上下文及目标版本，原子写历史并接受提案；不凭未绑定对象的一句“确认”擅自写入。失败不静默循环调用模型。
- 常规聊天可以检索已确认知识和当前提案，方便讨论合并与裁剪。知识是讨论整理结果，不因此成为已证实的外部事实或个人事实。
- 本机 Python helper 从认证只读导出接口增量写专用 vault（默认 Documents/Decision Knowledge），不改既有私人 vault；稳定 ID 目录内使用可读标题文件名（原生图谱按文件名显示节点），改名时重建全部受管链接，保留身份；生成领域索引、出处页、相关知识链接和历史页。只管理自己的清单，检测手改、symlink 和路径越界，冲突时不覆盖。无需 Obsidian 插件、云同步或开机自启。
- 同步进程随本项目 up/stop 管理；轮询仅 GET 不调用模型；本机同步状态可查。入库成功与文件同步成功分别报告。测试结束保留正式空知识库，不把合成用例当成本人的知识。

## 验收

未确认零知识写入；新增/跨对话合并/修订裁剪/条件并存/暂不保存；过期上下文与目标版本拒绝；重复请求和重启幂等；来源校验及有界覆盖说明；原有聊天/记忆/附件兼容；桌面与窄屏 UI；真实模型与认证 API；增量同步、改标题链接、用户文件与路径保护、断线重试；备份恢复。真实原件不写公开仓库，截图/模型输出仅留忽略目录。采集、通知、TGA、公网部署不在本轮范围。

## 当前限制

首版检索有界，不宣称全库完整冲突检测。整理基于对话文字及正式来源；附件原件不导出，不把读图推断冒充原文，缺直接依据时在提案与知识中明确。领域分类和模型建议需要本人审阅，Obsidian 单向镜像不接受回写。

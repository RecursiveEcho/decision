# 账号隔离与刷新体验

开始：2026-11-05（Asia/Shanghai）。状态：已集成并部署本机，工程复测完成；本人长期使用反馈仍待观察。

## 用户目标与已定边界

- 刷新时不要卡顿；先用实际浏览器性能数据定位，再改造成因，不用接口很快就推断页面很快。
- 允许自行注册。每个账号拥有独立的对话、记忆、资料、知识、附件、后台任务和模型上下文，注册后为空空间。
- 现有全部本机业务数据留给迁移后的管理员账号，原访问码和未过期旧会话保持可用。密码只存独立加盐的慢哈希，不能进入日志、网页构建和公开仓库。
- 当前共用 Wiki.js、Obsidian 镜像及观察设备仅给管理员，新账号不能调用这三条共用路径。启用新账号的外部集成须另做隔离设计。

## 实施与验收

A 负责数据库迁移、认证、服务端账号边界及任务/模型隔离；B 负责注册/登录、切换时清理本地状态和刷新卡顿修复；E 负责契约、备份、集成、隔离双账号验收与本机部署。接口见 `CONTRACT.md` 顶部。

上线前在独立数据库模拟 V8→V9，检查旧账号数据与旧登录；两个新账号互相猜测对话、附件、记忆、来源、知识、任务 ID，核对模型输入和导出不串。验证自助注册后空态、退出/重登、刷新及跨账号缓存清理。正式库在迁移前备份并实际恢复核验；正式部署后只读核对旧记录，合成账号留在隔离库。网页卡顿以浏览器 Network/Performance 的刷新前后同场景数据报告，不把接口耗时当作整页耗时。

## 已取得的诊断基线

生产本机认证后只读 HTTP：登录约21ms，活动对话列表8ms、归档7ms、记忆7ms、记忆概览6ms、资料5ms、主题4ms。数据量分别约19条对话、17条记忆、9份资料、6个主题。页面启动会串行 `loadProblems()`→`load()`；记忆页先加载全部记忆，再启动概览读取。这些接口数字不是整页性能数据，不能单独解释用户感受到的卡顿。

## 工程交付与实测

- A `f8d3755`、B `e99219d` 已合入集成。本机根后端140项、网页90项测试及 Maven/Vue/Vite 构建通过。V9 将旧数据归唯一管理员；注册返回会话并直接进入空空间，旧访问码和旧 owner 令牌兼容，会员访问共用 Wiki/设备受限。密码采用独立随机盐和 PBKDF2-HMAC-SHA256 600000 次，凭据幂等指纹由服务端 HMAC 生成。

## 当前边界

仍是本机环回地址，未部署公网或配置邮件验证/找回。公开注册若将来对外开放，需要另外决定 HTTPS、密码找回及模型调用额度，不能把本机验收当作公网安全验收。小程序仍走旧管理员访问码接口，未验收新账号登录；Wiki/Obsidian/观察设备仍只供管理员。用户自己的长期使用感受和具体卡顿场景不能由合成性能夹具替代。

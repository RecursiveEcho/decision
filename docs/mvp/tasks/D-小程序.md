# D：微信小程序薄客户端

先读 PROJECT_STATE、PLAN、CONTRACT。所有权 `miniprogram/`、`handoffs/D.md`。独立只读审查后实施；用户尚未创建小程序，不伪造 AppID 或假称真机已验收。

## 顺序

1. 原生小程序目录与页面配置；API_BASE_URL 可配置；统一 token/错误/Job 轮询；与网页共用本人的访问码和同一后端数据。
2. 登录、问题选择、聊天及资料提交（URL/正文）；显示发送/处理中/失败，重复点击不产生重复消息。可以先用显式 mock 开发页面，默认运行模式不隐藏 mock。
3. 议题列表、来源详情、决定查看；本人可点击确认记录决定和追加结果。避免外链不能直接打开导致流程死路：提供来源文本与链接复制入口。
4. 自检页面/配置/构建或导入能力。若本机有微信开发者工具，用真实工具验证；无账号只做实际可完成的检查，记录限制。
5. 给出本人创建 AppID 后最短接入步骤与服务器域名/HTTPS等需核验条件；不通过关闭安全校验把模拟器成功算真机成功。准备好之后复用当前实现，不重写后端。

手机通知不绑死微信订阅能力；首版客户端主要是聊天与查看入口。订阅消息能力按真实账号类目核验，禁止承诺任意主动推送。公网服务域名和小程序发布由 E 协调，不自行部署/发布或购买。

每阶段提交/推送 `feat/mvp-miniprogram`；handoffs/D.md 分别写代码、工具导入、真实 API、真机四项证据，以及开始/完成时间与剩余阻塞。

# A：后端与决策闭环

先读 PROJECT_STATE、PLAN、CONTRACT。独立只读审查后实施，不再调用递归审查。所有权 `backend/`、`handoffs/A.md`；不改共享契约和根配置。

## 顺序

1. 建 Java17/Spring Boot 3.5.x Maven 工程，锁定补丁版本、Maven wrapper、PostgreSQL/Flyway；补机器可读 API 文档。先完成登录、问题、资料、消息和 jobs；写首个回执供前端联调。
2. 接 DeepSeek 服务端 API；配置缺失、上游超时、限流必须有明确状态。实现本人陈述/观察/推断的记忆与证据引用；不能静默接受模型伪造的 sourceId/quote。
3. 接资料入库、受限制的 URL 提取、文章主题与 Wiki adapter。先保存来源再总结；实际 Wiki 版本由 E 提供，API 需核实；没配好要显示 pending_configuration。
4. 实现观察批量入库、device 权限、分析任务去重、议题和 Delivery；提供启动/暂停状态。新资料分析允许“无须提醒”，不能用每次强制推送假装智能主动。
5. 完成本人确认决定、追加复盘、记忆纠正与删除后的检索失效、模型用量；补必要失败/边界测试与 Dockerfile。

## 必须交付

- 契约路由、数据库迁移、可运行命令、模块环境项、构建及必要测试结果。
- 核实来源引用、重复提交、权限隔离、暂停后观察写入、删除后检索、失败任务恢复、决定不被 AI 自动确认这些关键行为。
- 无 key 可继续开发；mock 通过不能标真实模型通过。至少一次真实 DeepSeek 请求最终由 A/E 在安全环境配置后完成。
- Wiki 适配失败记录实际版本、请求类型和脱敏错误，不编造成功。

每个可联调阶段提交并推送 `feat/mvp-backend`，回执记录功能、开始/完成时间、提交、验证、待协调接口与遗留风险。用户原始数据不得用于公开测试夹具。

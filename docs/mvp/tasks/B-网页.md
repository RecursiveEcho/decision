# B：网页主入口

先读 PROJECT_STATE、PLAN、CONTRACT。所有权 `web/`、`handoffs/B.md`，独立只读审查后实施。使用 Vue3/Vite/TypeScript，依赖锁在 web 内，不能改根配置或后端。

## 顺序

1. 登录页+问题选择/创建+聊天主界面；API client 集中实现 token、错误、重试与 Job 轮询。契约样例可用于开发，但明确标 demo，不作为产品默认。
2. 资料入口支持链接/正文、获取状态、主题页与 Wiki 链接；回复可展开来源、不确定性，不把所有技术字段塞到聊天里。
3. 议题列表支持已读、稍后、忽略；记忆页展示本人陈述/观察/推断，提供纠正/撤销/删除。观察状态可见，启动与暂停必须显式操作。
4. 明确“确认记录决定”的动作；显示原理由和追加复盘；状态页显示模型/Wiki/采集是否配置。API 错误不能只在控制台出现。
5. 接 A 真实服务，检查刷新与重启后的数据。完成 `npm ci && npm run build` 与实际页面冒烟；交付 Dockerfile 或静态目录说明给 E。

优先可用、清楚的中文页面；桌面可用且窄屏不溢出。不会用响应式网页冒充小程序交付。不在前端保存 DeepSeek key；登录码不硬编码；通知正文不默认展示全部私密内容。

每个可联调阶段提交/推送 `feat/mvp-web`，写 handoffs/B.md：功能入口、开始/完成时间、验证命令与结果、mock/real 状态、待修问题。跨模块变更报 E。

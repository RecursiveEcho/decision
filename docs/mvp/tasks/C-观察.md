# C：电脑观察与桌面通知

先读 PROJECT_STATE、PLAN、CONTRACT。所有权 `observer/`、`handoffs/C.md`。独立只读审查后实施；本项目尚未启动观察器。

## 顺序

1. 核验 Pensieve 实际可安装版本、许可、Mac 文字/OCR与读取接口、默认截图保存路径/频率和启动行为。不要盲目运行会设置自启或立即录屏的便捷命令。
2. 做 Python3.11+ 独立环境适配器；界面或 CLI 必须能查状态、显式 run、pause、stop；默认暂停。先实现本地游标、device 心跳和上传接口。
3. 从 Pensieve 增量读取真实文字观察，生成稳定 externalId、contentHash、时间/应用/定位信息；去重、有限本地重试队列，断线后恢复不重复。当前绑定 problemId 由用户选择，不让模型凭空确定所有活动属于哪个问题。
4. owner 在服务端注册 device 后取得 scoped token；采集器只使用自己的 token。暂停后停止新提取和上传；不把暂停期间数据事后悄悄补传。真正停止 Pensieve 录屏的控制能力须验证；若仅能停止同步必须明确显示，不能冒充已停止采集。
5. 轮询后端 Delivery，显示真实 macOS 系统通知，回传 sent/failed；sent 不等于本人已读。通知点击进入网页中的对应议题（若首版点击能力未实现须标明），保证至少可从网页找到同一议题。
6. 用户明确开启后，在无敏感页面做短时真实试验，最后恢复暂停；检查中文提取、重复数据、断线、停止、重新启动。没有开启授权时交付待用户启动的组件，不私自试采。

不添加手机观察、录音、键盘记录或浏览器账号扫描。原始截图不上传本系统；Pensieve 自身保存策略必须查明、展示，不能声称截图自动销毁。记录真实资源占用与兼容问题，不预报 token 节省比例。

交付模块运行命令、依赖、设备配对步骤、真实/模拟检查区分。按阶段提交/推送 `feat/mvp-observer`，写 handoffs/C.md，不能修改 A 的 API 或 B 的页面。

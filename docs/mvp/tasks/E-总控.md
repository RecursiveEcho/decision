# E：共同起点、集成与可运行交付

本角色是当前主对话。拥有根目录、docs、deploy、scripts、handoffs/E.md 与 integration 分支。用户授权开发成果推送指定仓库；不自动合并 PR，不改 TGA，不将 GitHub 当运行服务器。

1. 建立文档基线、独立 worktrees 和角色任务卡；核验共同起点及远程地址。用户自行开四个开发对话，不声称已自动派发。
2. 根 `.env.example` 只放空密钥。引导用户在本机忽略的 `.env` 注入已有 DeepSeek key；不读取并打印 key，不把个人记忆放入公开 seed。
3. 准备可复用 Compose：业务后端、网页、PostgreSQL、Wiki.js。先核验镜像版本和架构，固定标签/摘要；业务库与 Wiki 库/用户隔离。避免暴露数据库、Pensieve和调试口；所有者登录默认必需。
4. 与 A 确定实际 Wiki 版本和访问 token；以只在本机运行的独立实例验证，不改任何已有服务。根脚本要检查缺失配置并报可理解原因；真实服务没准备好不能静默启用 mock。
5. 依次读取各 worktree 的 handoffs 并集成 A/B/C/D 可用提交，保护未提交修改。接口调整只由本角色更新 CONTRACT、版本和共享起点，再通知开发者同步。
6. 集成后执行必要检查：工程构建、登录权限、资料/模型/来源链、真实 Wiki 更新读取、观察启停、议题与真实通知、决定/复盘、持久化与备份恢复。截图测试只经本人开启。用户测试前修复已发现工程错误。
7. 填实际启动、关闭、访问地址；给出 USER_TEST 与待验项。MVP 合并进 integration 并推送，记录提交；未实现功能如实列出。
8. 测量本地总资源，再评估 TGA 服务器容量、端口、网络、隔离和备份要求。当前服务器尚未确定，不擅自占用 TGA 实例或对公网发布。

完成条件：用户可以按实际说明启动并试用真实闭环；小程序/手机通知/远程部署的实际状态明确。材料已准备不是产品已完成，工程检查通过不是用户已验收。

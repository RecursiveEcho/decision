# 图片、文件、思考与自动整理

2026-11-04 用户连续明确的新要求，当前实施中，不能沿用上一轮“视觉通过”替代本人反馈。

## 本轮目标与授权

- 输入框支持图片：粘贴、拖拽、选择、预览、移除、纯图发送及真实读图。
- 支持常见文档上传，选择真实生效的思考等级。
- 截图中引用铺成巨大绿色块不合适；改紧凑来源/引用入口，不确定性自然列表，完整信息仍可展开。
- 记忆应从正常聊天自动积累，查开源方法实现，不让用户手填；保留查看出处、纠正、忘记。
- E已读取B聊天的真实用户原话，核实其要求取消议题/服务与观察多余入口，决定记录由AI整理，不再填四字段表。明确选择由用户表达，AI负责记录，不代替本人做选择。采集仍关闭，旧数据不删除。

## 分工

A拥有backend：附件持久化/权限/Worker解析/真正视觉输入/思考参数、自动记忆与明确决定记录。B拥有web：输入区/本地附件草稿/可靠重试、紧凑证据、简化入口与可纠错记忆。E拥有契约、代理、集成与真实验收。独立只读需求/增量审查已通过。

## 已核实的外部依据

- [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)：现用deepseek-flash支持真正image_url块，沿用既有供应商，无新增key。
- [DeepSeek Thinking](https://api-docs.deepseek.com/guides/thinking_mode/)：off/low/high/max可映射真实参数，不做假选项。
- [Apache PDFBox](https://pdfbox.apache.org/)与[Apache POI](https://poi.apache.org/)提供成熟文档处理。只读审查指出当前请求事务持全局锁，因此解析必须Worker锁外；Future取消不等于硬终止，采用受限子进程。
- 开源记忆采用 [Mem0 v1.0.0 用户事实提取与更新方法](https://github.com/mem0ai/mem0/blob/v1.0.0/mem0/configs/prompts.py)，其 [实现](https://github.com/mem0ai/mem0/blob/v1.0.0/mem0/memory/main.py)先提取、检索再决定增删改，[许可 Apache 2.0](https://github.com/mem0ai/mem0/blob/v1.0.0/LICENSE)。在当前Java/PostgreSQL中适配该方法，重写适合本人原话与出处校验的提示，不引入SDK或宣称向量语义检索；不照搬上游提示中的不实来源描述。Hindsight需要更多检索/服务部署，本轮不引入。

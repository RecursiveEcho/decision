# D · 原生微信小程序

默认直连真实 API，无 mock 运行模式、无内置账号、无模型密钥。源码完成不代表微信工具编译、真实 API 或真机验收通过。当前证据见 `../handoffs/D.md`。

## 已实现

- 服务地址与本人访问码登录；与网页使用同一账号和服务器记录。访问码不持久化，token 仅存微信本机存储；退出登录或更换服务地址清除 token 和未完成 Job 引用。
- 问题分页选择和创建，目标、约束、未知条件分别提交。
- 聊天、URL/正文资料提交，202 Job 轮询、失败显示、断网查询退避、离页暂停查询、继续查询原 Job。Job ID 存在当前登录会话本机存储，不存消息正文。查询结束停止轮询；超时不会再次提交模型任务。
- 消息展示来源引用和不确定性；后端若返回 `mode: mock`，显示测试替身标识，不当成真实模型。客户端不构造证据。
- 议题、决定列表，来源全文和外链复制；明确弹窗确认后才能记录决定，复盘追加且不覆盖原理由。日期按设备本地时间显示。
- 创建操作加提交锁和 UUID 幂等键；同一进程内相同提交的网络/服务端不确定失败重试保留 key。客户端重启后不会恢复未知请求的幂等键，遇到提交中断应先刷新服务器记录，不应盲目重新创建。
- 不启动屏幕观察，不访问 Pensieve，不调用订阅消息或手机通知接口。

## 自检

需要 Node.js 18+；没有运行时 npm 依赖。在本模块目录运行：

```sh
npm ci
npm test
npm run check
```

`test` 使用明确的 wx/network 测试替身，覆盖请求幂等、认证隔离、轮询终态与取消、退避、分页去重、决定确认、资料提交。`check` 检查 JS 语法、JSON、页面文件、WXML 标签配对及事件处理函数；**不能替代微信 WXML 编译和布局检查**。

## 真实 API 联调（不依赖 AppID）

明确授权创建合成测试数据后，在模块目录运行：

```sh
node scripts/live-api.js /path/to/ignored/.env http://127.0.0.1:8080 --create-synthetic-data
```

脚本只读取忽略 env 的 `APP_OWNER_ACCESS_CODE`，不打印凭据、token、模型正文或文章内容。仅允许指定 loopback 服务，不启动后端或观察。每次创建独立的“D合成API验收”问题、文章、决定与复盘，会触发真实模型调用；没有删除问题的契约，故测试记录保留在服务端并带合成标记，不擅自删库。

它直接调用现有 `lib/api.js` 和登录/问题/工作区/来源页面处理函数，使用 Node 将 `wx.request` 适配为真实 HTTP；本机存储、导航、确认弹窗和剪贴板仍是宿主适配。**这证明客户端逻辑与真实 API 兼容，不证明微信渲染、复制界面、真实点击确认或真机网络通过。**

本次 2026-11-04 18:56（Asia/Shanghai）13 项检查通过：真实登录、创建与幂等重放/冲突、资料+Job、来源详情、未传 sourceIds 的真实模型回答（5 条引用逐字回查）、游标分页、议题读取、取消决定不写入、确认合成决定与追加复盘、404 Job 解锁、401 清会话。共 31 次 HTTP 请求，摄取与聊天 Job 均 `mode: real` 且成功。合成调用没有更改全局记忆，也未执行重分析管理接口。

脱敏运行报告写到模块 `.local/live-api-<时间>.json`，只留步骤结果、合成 ID、计数和错误码，Git 忽略；本次具体路径与证据见 D 回执。重复运行会新建一组数据，不把多次调用伪称同一次重试。

## 获得真实 AppID 后导入

1. 本人在微信公众平台注册并创建小程序，取得本人 AppID；账号类目、可用能力、隐私指引和发布要求以本人平台后台为准。无需将 AppID 或密钥写入公共仓库。
2. 在模块目录用本机环境变量提供 `WECHAT_APP_ID`，执行 `node scripts/prepare-import.js`。它生成被 Git 忽略的 `.local/wechat-project/`；不生成假 AppID，不上传或发布。每次源码更新都重新执行，以免导入旧副本。
3. 微信开发者工具选择“导入项目”，目录为上一步生成的 `.local/wechat-project/`，使用本人账号和 AppID。项目不依赖云开发或 npm 构建；保持 `urlCheck: true`。这里尚未实际执行导入。
4. 由 E 提供可达的 HTTPS 服务，微信后台配置对应的 request 合法域名，核验 TLS 证书、账号及备案等当前平台要求。开发者工具和真机都按实际环境验证，不把关闭域名校验后的结果算真机通过。
5. 小程序登录页填写服务器根地址（不含 `/api/v1`），再输入与网页相同的本人访问码。API_BASE_URL 就是该页面的“服务地址”，存本机，不进代码。开发时仅允许 localhost/127.0.0.1 的 HTTP 地址，但手机上的 localhost 指向手机自身，不能代替 HTTPS 服务。
6. 真机按下表测试，再把证据交 E 汇总；源码可准备不代表已经具备公网/发布条件。

## 最短联调检查

| 操作 | 预期 |
|---|---|
| 错误访问码、过期 token | 错误可见；401 回登录；不自动重复模型请求 |
| 与网页使用同一访问码 | 看到同一问题；刷新后数据一致 |
| 创建问题并连续点击提交 | 请求锁生效；相同不确定失败重试沿用幂等键 |
| 发消息、离开页面再进入 | 保留原 Job 引用，点击继续查询，不重新发送；完成后刷新记录 |
| 聊天超过 30 条 | 按契约时间升序分页，点击加载更多可到最新消息，不重复显示相同 ID |
| 发 URL；再用正文兜底 | 明确显示处理中/失败/成功，完整来源可回查 |
| 回查引用与复制链接 | 原文可选中，复制成功后可在外部浏览器打开；删除来源显示后端错误，不保留旧正文 |
| 查看议题、决定；取消/确认决定 | 取消不提交，确认才创建；复盘追加保留原决定 |
| 退出或换服务地址 | 清除登录凭证，旧 token 不发送给新服务 |

## 契约与外部限制

使用 `docs/mvp/CONTRACT.md` v1，未新增公共字段或路由。A 尚未提供可联调服务时，网络错误如实显示，不自动退回样例数据。消息、资料、决定等数据只从服务端获取，不另建个人记忆。

微信官方 `RequestOption.method` 当前类型列表不含 PATCH，而共享契约用 PATCH 处理议题状态。因此 D 只实现任务卡要求的议题列表，处理已读/稍后/忽略请用网页。未使用未经 E 确认的 POST 别名或 method override；若需小程序内处理，由 E 统一调整契约，A 实现后再接入。

总控已在集成契约新增 `POST /problems/{id}/analyze`：由本人显式重分析，携带 owner token 与 Idempotency-Key，提交 `{}` 后返回 202 analysis Job。D 本轮不接入此管理操作；**失败后的重分析请使用网页**，不要靠重复提交原资料触发重分析。
